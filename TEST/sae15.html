SAÉ 1.5 : Traiter des données

Conception d'un projet de développement et manipulation de données

I. Contexte et cahier des charges

Ce projet, réalisé dans le cadre de la SAÉ 1.5, avait pour objectif de concevoir un programme en Python capable de collecter, traiter et mettre en forme des données provenant de sources externes. Le cahier des charges imposait une réalisation en autonomie complète, structurée autour de l'utilisation d'API (REST) pour interroger des services web. Le projet devait permettre de manipuler des formats de données structurées (JSON) et d'utiliser des bibliothèques de traitement d'images (type Pillow) pour automatiser la création de documents ou de cartes. L'enjeu était de démontrer notre capacité à intégrer des données dynamiques dans une application fonctionnelle, tout en respectant les bonnes pratiques de développement (code propre, modularité).

II. Vocabulaire technique utilisé

  • API REST : Interface permettant à notre programme de communiquer avec des services web pour récupérer ou envoyer des données de manière standardisée.
  • Format JSON : Format léger d'échange de données structurées, très utilisé par les APIs pour transmettre des informations lisibles par machine.
  • Bibliothèque Pillow : Bibliothèque Python utilisée pour la manipulation et la transformation d'images (assemblage, ajout de marqueurs, traitement graphique).
  • Markdown : Langage de balisage léger utilisé pour formater la documentation du code et présenter les résultats de manière lisible.
  • Autonomie de développement : Démarche consistant à résoudre des problématiques techniques sans assistance directe, propre à la conduite de projet professionnel.

III. Apprentissages Critiques (AC) et Bilan

  • AC - Programmer (RT3) : Ce projet a consolidé ma maîtrise du langage Python. J'ai appris à concevoir une architecture logicielle capable d'interagir avec le Web. L'utilisation d'API pour extraire des données réelles et les traiter a transformé mes compétences théoriques en une solution logicielle concrète.
  • AC - Développer une démarche méthodologique : La gestion du projet en autonomie a été formatrice. J'ai dû structurer mon code, gérer les erreurs potentielles lors des appels API et organiser mes fonctions pour assurer la maintenabilité de l'application. Cette approche "projet" a été essentielle pour respecter les délais.
  • AC - Traitement des données : J'ai réalisé l'importance de la structuration des données. Passer d'une réponse brute (JSON) à une information exploitée (image, texte, carte) m'a permis de comprendre le cycle complet du traitement de l'information dans une infrastructure réseau.

IV. Méthodologie et étapes de mise en œuvre

1. Analyse et Planification

Cette phase a consisté à analyser les documents fournis par le professeur afin de définir le périmètre du projet. Nous avons identifié les types de données spécifiques à extraire depuis l'API OpenStreetMap, dont l'utilisation était imposée par le cahier des charges. Pour mener à bien ce développement, nous avons fait le choix de travailler en binôme, directement sur le même fichier de code et en simultané. Cette méthodologie de travail s'est avérée très efficace : lors des blocages techniques, cette collaboration immédiate nous permettait de confronter nos réflexions et de trouver rapidement des solutions. En parallèle, nous avons structuré notre projet en fonctions dès le départ pour faciliter le développement et assurer une bonne modularité.

2. Développement et Interrogation API

Cette phase a constitué le cœur technique de notre projet. Nous avons développé les scripts en Python pour effectuer les requêtes HTTP vers l'API. Manipuler des API étant une première pour nous, nous avons initialement rencontré des difficultés pour en appréhender le fonctionnement. Toutefois, nous avons réussi à surmonter cet obstacle en nous appuyant sur les documents fournis par l'enseignant ainsi que sur des vidéos éducatives. Ces ressources ont été déterminantes pour comprendre la nature et le mécanisme des échanges de données. Concrètement, notre script fonctionne en envoyant des requêtes HTTP ciblées vers le service d'OpenStreetMap. Une fois la connexion établie, le programme réceptionne les données structurées (format JSON), les analyse, et les traite selon nos besoins. Nous avons également intégré des mécanismes de gestion des exceptions afin de garantir la robustesse et la stabilité de notre application.

3. Traitement des données et Manipulation d'images

Cette phase constitue l'aboutissement visuel de notre projet. Après avoir récupéré les données brutes au format JSON, nous avons procédé à leur transformation en un rendu graphique exploitable via la bibliothèque Pillow. Le processus s'est articulé autour de trois étapes : extraction et parsing, traitement graphique (mapping des coordonnées), et assemblage des annotations. Analyse de la démarche : Le défi majeur a été la précision mathématique pour la conversion des coordonnées. Cette étape a été extrêmement formatrice, car elle m'a permis de comprendre le lien indispensable entre le traitement pur de l'information (backend) et sa restitution visuelle intelligible pour l'utilisateur final.
